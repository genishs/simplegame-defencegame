- **실행 환경**: Windows 11 (개발 머신 또는 릴리즈 .exe)

## CAT-01: 게임 첫 실행 ~ 메인 메뉴 응답성

### 1) 사전 조건
- 저장 데이터 없는 클린 상태 (또는 `%APPDATA%\AnsiseongDefense` 폴더 삭제)
- Python 환경: `python src/main.py` 또는 .exe 더블클릭

### 2) 실행 절차
1. 게임 실행 명령어 또는 .exe 파일을 실행한다.
2. 스톱워치(또는 핸드폰 타이머)를 시작한다.
3. 메인 메뉴 화면이 나타나고 버튼 8개가 표시되는 시점에 타이머를 멈춘다.
4. 마우스 커서를 버튼 위에 올려 hover 효과(색상 변화)가 발생하는지 확인한다.
5. Up/Down 화살표 키로 포커스가 이동하는지 확인한다.

### 3) 기대 결과
- 메인 메뉴 표시까지 **3초 이내** 완료
- 타이틀 텍스트 "안시성: 88일의 약속" 가 한글로 정상 표시 (깨짐 없음)

## CAT-02: Stage 1 전 구간 손맛 (영웅 M키, 스킬, 아군 배치, UI 클릭 반응)

### 1) 사전 조건
- 메인 메뉴에서 "새 게임" 또는 "스테이지" 선택 후 Stage 1 진입
- 영웅 체력 (기본 800 HP) 확인

### 2) 실행 절차
1. 메인 메뉴 → "스테이지" 버튼 클릭 → Stage 1 "요동성의 첫눈" 카드 클릭 → "도전하기"
2. 배틀 씬 진입 확인 (적 웨이브 지연 카운트다운 시작)
3. **M 키** 를 눌러 직접 조작 모드 ON 확인:
   - 화면 우측 상단 "직접 조작 모드 ON" 라벨 표시 확인
4. WASD / 방향키로 영웅을 이동시켜 이동 반응이 자연스러운지 확인
5. 적이 등장하면 영웅 자동 모드(M키 OFF)로 전환
6. Wave 1 종료 후 Wave 2 시작 확인 (카운트다운 표시)
7. **Esc 키** → 일시정지 다이얼로그 표시 확인 → "재개" 클릭
8. 모든 웨이브 소진 후 승리 화면 → "메뉴" 버튼 클릭 → 메인 메뉴 복귀

### 3) 기대 결과
- M키 토글 시 즉각적인 라벨 전환 (딜레이 없음)
- 영웅 이동: 방향키/WASD 모두 동일 속도(150 unit/s), 대각선도 동일 속도
- 적 웨이브 카운트다운 숫자가 감소하면서 표시됨
- 일시정지 다이얼로그 표시 중 게임 로직 중단 확인
- 승리 조건 충족 시 ResultDialog 표시 (재도전 / 메뉴 버튼)
- 메뉴 복귀 시 메인 메뉴 정상 표시

### 4) 검수자 메모

## CAT-04: 폰트 한글 렌더링 (Malgun Gothic 미설치 환경 가정 시 Noto Sans KR 폴백)

### 1) 사전 조건
- **시나리오 A** (번들 폰트 우선): .exe 빌드 버전 사용 (Noto Sans KR OTF 번들 포함)
- **시나리오 B** (폴백 검증): Python 개발 환경에서 assets/fonts/ 디렉터리를 임시 비워두고 실행

### 2) 실행 절차

**시나리오 A — .exe 번들 폰트**
1. `dist/AnsiseongDefense/AnsiseongDefense.exe` 실행
2. 메인 메뉴에서 한글 텍스트("안시성: 88일의 약속", "새 게임", "스테이지" 등) 확인
3. 스테이지 선택 씬으로 이동하여 스테이지 이름("1. 요동성의 첫눈" 등) 확인
4. 배틀 씬 HUD의 골드/HP 등 숫자+한글 혼용 텍스트 확인

**시나리오 B — Malgun Gothic 폴백**
1. `assets/fonts/` 폴더의 `.otf` 파일을 임시 다른 위치로 이동
2. `python src/main.py` 실행
3. 한글 텍스트가 Malgun Gothic으로 표시되는지 확인 (시스템 폰트 폴백)

### 3) 기대 결과

**시나리오 B**
- Malgun Gothic(시스템 폰트)으로 폴백하여 한글 정상 표시
- 게임 에러 없이 실행 지속

## CAT-05: 튜토리얼 첫 실행 자동 진입 손맛 (8단계 자연스러움)

> Phase 4 신규 | 기준: docs/12_tutorial_design.md (DECISION-PL-P4-001~003) | QA Lead 등록

### 1) 사전 조건

### 2) 실행 절차
1. 게임을 실행한다.
2. 메인 메뉴에서 **"새 게임"** 버튼을 클릭한다.

4. 튜토리얼 단계 1이 자동으로 시작되는지 확인한다.
5. **단계 1~8을 순서대로 진행하며 각 단계의 CTA(진행 버튼/키 입력)를 확인한다**:
   - 단계 1: "다음" 버튼 클릭 → 단계 2 진입

## CAT-06: 난이도 하향 후 stage 01~03 자동 모드 클리어율 (5회 시도 → 5회 클리어 기대)

> Phase 4 신규 | 기준: docs/13_difficulty_balance.md (DECISION-PL-P4-012) | QA Lead 등록
> BL-07 시나리오의 수동 검수판 — 자동 모드 mock 시뮬레이션이 미구현인 시점까지 수동으로 진행

### 1) 사전 조건
- Dev Team1(Issue #27) 데이터 패치 머지 완료 후 실행 가능

- Python 환경 또는 .exe 빌드
- **영웅 M키 수동 모드 사용 금지** — 자동 모드(AI 위임)만 사용

### 2) 실행 절차

**stage_01 검수 (3회 시도)**
1. 새 게임 또는 스테이지 선택 → stage_01("요동성의 첫눈") 진입.
2. M 키를 누르지 않고 자동 모드로 유지.
3. 기본 유닛(궁수) 1~2개만 배치하고 wave 진행 관찰.
4. 3 wave 모두 소화 후 클리어 여부 확인.
5. 동일 조건으로 **총 3회** 시도 후 클리어 횟수 기록.

**stage_02 검수 (3회 시도)**
1. stage_01 클리어 후 stage_02("백암성의 항복") 진입.
2. 자동 모드 유지, 기본 유닛 배치만.
3. **4 wave** (패치 후) 소화 후 클리어 여부 확인.
4. 총 3회 시도.

**stage_03 검수 (3회 시도)**
1. stage_02 클리어 후 stage_03("개모성의 횃불") 진입.
2. 자동 모드 유지. 야간 시야 상태에서 단일 path(W1) 및 다중 경로 wave 처리.
3. **4 wave** (패치 후) 소화 후 클리어 여부 확인.
4. 총 3회 시도.

### 3) 기대 결과
- stage_01: **3회 시도 → 3회 클리어** (100%, 최소 2/3)
- stage_02: **3회 시도 → 3회 클리어** (100%, 최소 2/3)
- stage_03: **3회 시도 → 3회 클리어** (100%, 최소 2/3)
- 전체 9회 시도 합산 **95%+ 클리어율** (최소 9회 중 9회)
- 각 stage reward.grain 정확값 확인: stage_01=100, stage_02=150, stage_03=220

## CAT-07: M키 영웅 수동 모드 + 튜토리얼 6단계 일시정지 UX

> Phase 4 신규 | 기준: docs/12_tutorial_design.md §2.6 (DECISION-PL-P4-003), docs/03_game_design_document.md | QA Lead 등록
> CAT-02(Stage 1 손맛)의 Phase 4 확장판 — 튜토리얼 6단계 문맥에서 검증

### 1) 사전 조건
- Dev Lead(Issue #26) 머지 완료 후 실행 가능
- 튜토리얼이 미완료 상태 (또는 메뉴에서 튜토리얼 재진입)

### 2) 실행 절차

**파트 A — 튜토리얼 5단계 M키 수동 모드**
1. 튜토리얼을 단계 5까지 진행한다.
2. 단계 5 텍스트("M 키를 누르면 직접 움직일 수 있소")가 표시된 상태에서:
   - **M 키** 1회 입력 → 영웅 수동 모드 ON 확인 (라벨 변경 + spotlight)
   - WASD/방향키로 영웅을 이동시켜 반응 확인
   - **M 키** 1회 더 입력 → 자동 모드 복귀 확인
   - 단계 5 20초 제한 fallback 없이 단계 6 진입 확인

**파트 B — 튜토리얼 6단계 일시정지/재개 UX**
1. 단계 6에 진입한다.
2. 단계 6 텍스트("스페이스 키를 누르시오") 표시 확인.
3. **스페이스 키** 1회 입력 → 게임 일시정지 확인 (타이머/wave 중단).
